# Musaix

AI drum pad for producers. Type a genre, play a 16-pad kit, and route MIDI into Ableton, Logic, or FL Studio.

Live site is deployed on Vercel from this repository.

## What's here

- **Landing page** (`src/routes/index.tsx`, `src/components/landing/`): hero, a playable 16-pad demo, how it works, MIDI routing, pricing, testimonials, FAQ, and a waitlist signup.
- **Pad demo** (`src/lib/kits.ts`, `src/lib/audio.ts`): genre kits with 16 pads, a BPM and a one-bar groove. Pads play from the keyboard in a 4×4 grid:

  | Row    | Keys            |
  | ------ | --------------- |
  | Top    | `1` `2` `3` `4` |
  |        | `Q` `W` `E` `R` |
  |        | `A` `S` `D` `F` |
  | Bottom | `Z` `X` `C` `V` |

- **Auth** (`src/lib/auth/`, `migrations/auth/`): "Sign in with Grok" via Better Auth. It uses Postgres when `DATABASE_URL` is set and a local PGLite database otherwise.
- **Don Sterleone** (`public/don-sterleone/`): a standalone neon-noir three.js driving game, served as-is at [`/don-sterleone/`](public/don-sterleone/). It has its own [README](public/don-sterleone/README.md).

## Stack

TanStack Start (React 19 + TanStack Router), Vite with Nitro, Tailwind CSS 4, Radix UI, Better Auth, Kysely, and Postgres (or PGLite locally).

## Getting started

```bash
npm install
npm run dev        # http://localhost:8080
```

`dev`, `build` and `preview` run through `scripts/with-app-env.mjs`, which merges the `VITE_` keys from `.grok/app-env.json` into the environment before Vite starts. A variable that's already set in your shell takes precedence.

### Scripts

| Command              | What it does                                                                  |
| -------------------- | ----------------------------------------------------------------------------- |
| `npm run dev`        | Dev server on port 8080                                                       |
| `npm run build`      | Production build, then apply database migrations                              |
| `npm run preview`    | Serve the production build                                                    |
| `npm run typecheck`  | `tsc --noEmit`                                                                |
| `npm run lint`       | ESLint                                                                        |
| `npm run format`     | Prettier                                                                      |
| `npm test`           | Node test runner over `scripts/**/*.test.mjs` and the app-data and auth tests |
| `npm run db:migrate` | Apply SQL files in `migrations/` that haven't run yet                         |

### Environment

| Variable            | Purpose                                                                                |
| ------------------- | -------------------------------------------------------------------------------------- |
| `DATABASE_URL`      | Postgres connection string. Without it, the app falls back to a local PGLite database. |
| `VITE_AUTH_ENABLED` | Turns the sign-in flow on or off in the browser build.                                 |

## Database migrations

SQL files in `migrations/` are applied in order, and each file is recorded by name in a `_migrations` table so it never runs twice. `0001_auth.sql` is generated by Better Auth, so don't edit it by hand. Add your own schema as new files (`0002_*.sql`, `0003_*.sql`, and so on).

## Deploying

Vercel builds the site with the settings in `vercel.json`: install with `npm ci`, then run `node scripts/with-app-env.mjs vite build`. `npm ci` fails if `package-lock.json` is out of sync with `package.json`, so commit the lockfile whenever you change dependencies.
